# dsh-im-bridge

[中文](README.md) | [English](README.en.md)

**在飞书里，继续你桌面里那个正在跑的会话。**

不是另开一个 agent，不是转发消息再复制回来——是同一条对话、同一份上下文、同一批文件。
手机发一句，桌面接着干；它干到一半，你在手机上插一句，它能当场改方向。

---

## 为什么用它

### 同一个会话，不是新的 agent

这是它和"把消息转发给另一个 AI"最根本的区别：那些方案里，你要在手机上重新交代背景、
重新等它读完文件、重新建立上下文；这里什么都不用做——继续的就是**桌面里那个会话**：
历史、已打开的文件、工具授权、模型选择，全都接着用。

### 长任务看得见它在动

跑一个几分钟的任务时，飞书里会出现一张**会变的卡片**，同一条消息原地刷新：

```
🔄 正在处理（第 12 轮 · 已 2m12s）

▶ pwsh  Probe a four second 1080p video generation  1m02s · 进行中
✓ pwsh  ffmpeg -i clip_01.mp4  18.2s
· 子 agent 调研回调机制  35s · 进行中

共 3 条 · 刚刚更新
```

显示的是工具调用、子 agent、耗时——**模型自己写的那句人话描述**，不是一长串命令。
固定显示最近 5 条，早期的滚掉，底部保留总数。

不想看就关掉：

```
/progress off    关掉进度卡片
/progress on     重新打开
/progress        拉取这一轮的完整事件列表
```

### 不需要公网 IP

插件从你的机器**主动**连飞书的长连接。不监听端口、不做内网穿透、不配域名和证书，
也没有需要暴露在外的地址。改防火墙入站规则也不影响它。

### 跑到一半也能改方向

大多数机器人只能在"这一轮跑完"之后接收下一句。这个插件把消息**插进正在跑的那一轮**：

```
你：把这三步依次跑一下，每步 30 秒
它：（第 1 步执行中）
你：别跑第 3 步了，先说结论
它：（第 2 步跑完就停，直接给你结论）
```

只有注入发生在 DSH 进程内部，才做得到这件事。

### 文件双向：发得出去，也收得进来

**发**：图片、视频、音频、文档，agent 一次调用就发到聊天里。

**收**：在飞书里直接把文件拖进来或拍照发过来，插件会下载到
<项目目录>/.dsh-im-bridge-inbox/YYYY-MM-DD/，并把这个消息转给 agent。
图片会**直接作为图片**交给模型（它能看见图，不是给个路径猜），
其它文件给路径；单个文件上限 100 MB。

```bash
dsh-feishu-send-file --file 剧本.md
dsh-feishu-send-file --file 成片.mp4 --cover 封面.jpg
```

### 进度问得到，也能随时叫停

```
/status
```
```
- 是否正在跑：是
- 上一轮 turn：`590`
- 正在运行的后台任务（2）：
  - `pwsh` python render.py --batch 3 — 已运行 12m40s
- 正在运行的子 agent（1）：
  - 调研回调机制 — 已运行 3m12s
- 排队中：1 条（等这一轮结束）
- 模型：opencode-go / deepseek-v4.1-flash
```

`/stop` 立刻停下当前这一轮；`/model` 换模型（也可以直接 `/model 2` 选编号）。

### 不想打断，就排队

句首加 `#`：不插入当前轮，等它跑完再处理。不加 `#` 就是立刻插进去。

### 没有第二个进程

它就是一个 DSH 插件，住在 DSH 里。不需要守护进程、不需要开机自启、不需要另配账号登录。

## 装上

### 1. 安装插件

DSH 侧栏 → **插件** → **已安装** → **安装**，填：

```
github:danleivv/dsh-im-bridge
```

确认信任提示，按提示重启 DSH。

### 2. 拿到飞书应用凭据

```bash
dsh-feishu-setup
```

它打印一个链接，手机飞书扫码确认，应用凭据**自动写入本机**（不经过对话、不经过命令行参数）。

> 组织策略不允许这种方式时，也可以去飞书开放平台手工建应用，再用
> `dsh-feishu-setup-manual` 以隐藏输入的方式写入。两条路最终都在本机落一个文件。

### 3. 打开卡片回调（用选项卡才需要）

`/model` 和 `/perm` 发的是可点的卡片。要让点击回到插件，需要在飞书开放平台给应用加上：

```
事件订阅 → 添加事件 → 卡片回传交互（card.action.trigger）
```

不加也能用——只是那两个卡片点了没反应，`/model provider/model` 和 `/perm 2` 这类文字指令照常工作。

### 4. 重启 DSH

凭据在插件启动时读取，改完要重启一次。

### 5. 在飞书里发句话

第一句发出去，插件会把该填的映射打进日志，复制进配置即可（见下）。

## 用起来是什么样

| 你发 | 会发生什么 |
|---|---|
| `跑一下今天的渲染` | 一轮任务开始，回复以卡片发出，超过几十秒的任务会带上进度卡 |
| 任务跑着时再发一句 | **插进当前这一轮**，并立刻回「已接收消息，当前工具调用结束后响应」 |
| `#等这轮跑完再总结` | 回「已收到，等当前这一轮结束后发送」，这一轮**不受干扰** |
| `把产物发我` | agent 直接把文件发到聊天 |

### 指令

| 指令 | 作用 |
|---|---|
| `/status`（旧写法 `?status`） | 在跑什么、后台任务、子 agent、排队数、当前模型 |
| `/stop` | 停下当前这一轮，残余输出不再发出 |
| `/model` | 弹出**模型选项卡**，点一下就切（也可 `/model provider/model`，下一轮生效） |
| `/perm` | 弹出**权限选项卡**：完全权限 / 只写工作区 / 仅可查看 |
| `/progress` | 拉取这一轮完整事件列表 |
| `/progress on` / `off` | 开关进度卡片（按聊天记忆，重启仍有效） |
| `/mirror on` / `off` | 把桌面端的对话同步到飞书（默认关闭） |
| `/help` | 指令说明 |

`/model` 和 `/perm` 发的是同一条卡片：**点按钮 → 原地变成「已切换」**，不用记编号、不用重发指令。

> 权限切换改的是**这个会话本身**：你在手机上点「仅可查看」，桌面那边也会立刻变成只读。

只有这几个开头的消息会被当成指令；`/etc/hosts` 这种照常发给 agent。

回复以卡片发出，**粗体、表格、代码块**都会正常渲染——包括手机端。

### 把桌面端的对话同步到手机

默认关闭。发一次 `/mirror on` 之后，你在电脑上打的字、以及 DSH 的回复，都会出现在飞书里：

```
📱 桌面端发来

> 把第三镜重拍一下，别动前两镜
```

**为什么默认关**：这会把电脑上的对话内容推到飞书服务器，公司租户可能被审计。需要时再开，
`/mirror off` 随时关掉，开关按聊天记忆。

### 三种权限分别是什么意思

| 选项 | 含义 |
|---|---|
| **完全权限** | 允许一切工具，可写任意路径。跑批量任务时最省事，也最危险 |
| **只写工作区** | 只能改项目目录内的文件；动目录外的东西要确认 |
| **仅可查看** | 只读。任何写入都要先问你 |

切换是**整个会话级别**的：飞书上改完，桌面那个会话立刻用新策略。跑完批量任务想收一收权限，
在手机上点「仅可查看」就行，不用回桌面。

## 配置（一次就好）

两个文件都在 `~/.dsh-im-bridge/`：

| 文件 | 作用 | 什么时候读 |
|---|---|---|
| `config.json` | 允许哪些会话、哪个聊天对应哪个会话 | 每次请求，改完即时生效 |
| `gateway.json` | 凭据、开关、渲染与行为 | 插件启动时，改完要重启 |

### `config.json`

```json
{
  "allowSessions": ["session-xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"],
  "sessionKeys": {
    "feishu:oc_xxxxxxxxxxxx:ou_yyyyyyyyyyyy": "session-xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
  }
}
```

第一次发消息后，插件会把这行原样打进日志，复制进 `sessionKeys` 即可：

```
pin it with: "sessionKeys": { "feishu:oc_xxx:ou_yyy": "<会话 id>" }
```

`allowSessions` 是白名单：**留空等于谁都不允许**，可以当急停开关用。

### `gateway.json`

通常**不用手改**——凭据由 `dsh-feishu-setup` 写入，其余走默认值。
想调的话（渲染方式、忙碌行为、前缀、表情名、进度卡开关、语言）见
[`gateway.json.example`](gateway.json.example)。

#### 界面语言

插件的设置里有一个**语言**下拉框（中文 / English），默认中文。选 English 之后，飞书里收到的
所有回复、进度卡片、错误提示都变成英文；**日志不受影响**（日志保持原样，方便排障）。

也可以直接写进 `gateway.json`：

```json
{ "language": "English" }
```

#### 其它常用开关

```json
{
  "progressCard": true,
  "progressAllTurns": true,
  "deliver": "live"
}
```

- `progressCard`：进度卡片总开关
- `progressAllTurns`：桌面端发起的轮次也推卡片（默认开，关掉只管飞书发起的）
- `deliver`：`live` = 边跑边发，`turn-end` = 跑完一次性发

想用环境变量而不是文件：

```bash
export FEISHU_APP_ID=cli_xxxxxxxxxxxxxxxx
export FEISHU_APP_SECRET=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

## 常见问题

**桌面 App 关了还能用吗？**
不能。插件住在 DSH 进程里，App 关掉就断了。这是"共享同一个会话"的代价。

**进度卡片会刷屏吗？**
不会。它始终是**同一条消息**，内容原地刷新，不触发新消息通知。

**选项卡点了没反应？**
说明飞书那边的卡片回调没开。去开放平台 → 事件订阅 → 添加 `卡片回传交互
（card.action.trigger）`，再重启 DSH。不修也能用文字指令：`/model provider/model`、`/perm 2`。

**能同时用两个会话吗？**
一个飞书应用一条长连接、对应一个会话；多个会话就配多个应用。

**别人会给机器人发消息吗？**
第一个发消息的人会被自动绑定为唯一使用者，之后其他人的消息直接忽略。

**密钥存在哪？**
`~/.dsh-im-bridge/gateway.json`，权限收紧到当前用户；仓库和发布包里都没有凭据。

**要装别的软件吗？**
不用。这个插件自己连飞书。

## 安全边界（请先读这一段）

**收文件只做了简单的文件名消毒，不是安全审查。**

插件会做的事：

- 去掉文件名里的目录成分（`../`、`C:\`、`/etc/` 之类）
- 去掉控制字符和 Windows 非法字符，处理 `CON`、`nul` 这类保留名
- 同名文件加 `-1` 后缀，不覆盖已有文件
- 把文件写进固定的收件目录，不写到别处

插件**不会**做的事：

- 不扫描文件内容，不查病毒、不查宏、不查可执行文件
- 不判断文件是否恶意、是否伪装扩展名（`invoice.pdf.exe` 照收）
- 不做内容沙箱，文件落在真实磁盘上
- **无法保证消毒规则覆盖所有绕过手法**——这是一层简单的字符串处理，不是安全机制

**因此：文件的来源与安全性由你自己负责。** 只接受你信任的人发来的文件；不确定的文件
先在沙箱或虚拟机里看。agent 拿到的是真实路径和真实内容，它不会替你判断这个文件能不能打开。

同一个前提也适用于账户层面：谁拿到这个机器人，谁就能驱动你桌面上那个会话（工具授权、
文件读写都在那个会话的权限下）。所以**第一个发消息的人会被自动锁定为唯一使用者**，
换人用之前请先清掉 `gateway.json` 里的 `allowUsers`。

## 已知限制

- 桌面 App 必须开着。
- 收文件的安全边界如上：只做文件名消毒，文件内容不做任何检查，**存在绕过的可能**。
- 单个文件上限 100 MB（飞书资源接口的限制）；超过会跳过并提示。
- 布局固定的进度卡片只显示最近 5 条，更早的会滚掉；要完整列表发 `/progress`。
- 进度卡片只显示工具调用与耗时，**不显示模型的推理原文**。
- 工具授权弹窗只在桌面出现，手机那头会一直等。
- 一个飞书应用只能有一个长连接消费者；同时连两个会分摊事件。
- 状态表情（收到 / 处理中 / 完成）在部分环境会失败，不影响消息送达。
